# 自然语言零件和装配

`spec.py` 定义跨供应商的严格数据结构和小型能力目录。理解模型输出完整方案，
缺少尺寸先追问；执行模型只调用一次受限工具，应用按阶段串行执行原生API。
允许板件、L形截面支架、圆轴、开口矩形壳体、拉伸/旋转轮廓与本机SLDPRT输入。
此目录没有动态Python/COM表达式或模型提供的任意路径。

零件/装配预览使用统一清单。装配以实测固定底座局部X为左右、Z为高度，前视看+Y，右视看-X，俯视看-Z；
相机矩阵通过原生Orientation3回读，四张PNG与中英文视图ID、标签、哈希随包交付。预览前显式激活并核对目标文档路径。
复核输出结构化preview_issues。遇到朝向、标签、空白、缺图或旧任务缺少清单时，Terra可调用一次受限原生工具
重出预览并另存交付ZIP，再由Sol按最新四图及上一轮全部问题再次复核。几何未通过时不进入预览修正，
再次不通过保留问题；不重放建模、不改变配合或固定组件。每轮复核、旧预览和旧包保留。界面只把当前清单四图作为主预览。
已有任务可点击“重新复核预览”，在新任务中复用经哈希验证的模型，保留原任务与模型文件。

所有尺寸为毫米。生成零件的Front Plane为XY，沿+Z拉伸。板件以XY居中；
L支架的length沿X、height沿Y、width为Z方向拉伸深度。轴从Z=0沿+Z延伸。
实例位置是最终原点位置，旋转为XYZ欧拉角。配合中的XY/XZ/YZ分别为Front/Top/Right。
距离配合的距离指所选基准面的距离，板面净间隙需要结合厚度换算。

结构化零件/装配规划使用16384输出Token的有界上限，以容纳多个零件、实例和完整配合字段；
该上限不是实际用量。OpenAI Responses返回的模型、响应ID、状态和usage写入任务事件，
不记录密钥或HTTP头。被截断的响应也保留真实usage，不因SDK尚未触发完成回调而误记为零。
达到输出上限时停止，不以相同容量盲目重试，也不把不完整方案送入CAD。
规划模型实际读取的能力目录明确列出该原生工具内置的重开、STEP重导入、BOM和ZIP流程，
不要求存在同名的独立工具。平面配合在写入CAD前按实例旋转及目标位置检查法向平行、
距离、正负方向和alignment一致性；错误方案不能以全部固定组件的方式绕过。

界面可分别保存规划/复核与执行的思考强度。DeepSeek显式MAX时发送
`reasoning_effort=max`和`thinking.type=enabled`，各角色输出上限为131072，HTTP超时设置为600秒；
不自动降档。思考内容只在SDK内部按DeepSeek协议回传，不进入普通任务日志；任务事件只记录
实际参数、响应ID、状态、延迟与usage。旧设置未指定强度时保留原分工，不追改历史任务。

OpenAI的`gpt-6-astra`、`gpt-6.1-sol`和`gpt-6.1-terra`显式MAX时，规划、执行与复核均发送
`reasoning.effort=max`，输出上限为128000，HTTP超时为600秒。其他强度保留原容量；未知模型不推定
支持该上限。上限容纳思考与最终输出，按实际返回用量计费。Responses任务事件记录实际请求强度、
上限、返回模型、延迟及包含缓存/思考Token的usage，不记录隐藏思考正文。成功响应只统计一次；
SDK拒绝的截断响应仍保留用量。模型返回错误时不自动降级到其他模型。

规划和复核的DeepSeek Chat请求同时开启供应商JSON模式；空白或不合格内容仍拒绝执行，并只作一次有界重规划。工具执行回合不强制JSON模式。

装配至少有两个实例且仅一个固定基座，其他实例必须由真实配合连接。支持重合、距离、
同心配合；同心配合按指定半径查找原生圆柱面。默认要求完全定位，allow_motion仅允许
保留自由度，不表示完成运动学测试。干涉检测、保存重开、实例位置与约束状态均读取
实际SolidWorks对象，不根据规划参数伪造验收。

相同孔径的多个圆柱面需要给出各零件局部坐标中的轴上一点，选择不唯一时停止，
不凭面积任意选孔。配合验收回读真实引用组件、平面名称/圆柱半径及距离尺寸。

`native.py` 每阶段保存一次检查点。输入方案、阶段号或文件哈希改变即停止；取消发生
在阶段间，进入SolidWorks的调用不能强行撤销。仅明确“调用被拒绝”的RPC可有限重试，
其他写入失败不自动重放。一个模型结构错误允许一次规划修复，不执行CAD写入。
180秒为软等待阈值，进入COM的操作必须返回后才结束请求，避免MCP客户端清理进程时
截断仍在执行的调用。界面等待期间持续提示，Stop仅阻止下一阶段。

`native_io.py` 对已命名文档调用Save3；新文件使用IModelDocExtension.SaveAs3。
已有零件用Silent|Copy保存原生副本，核对源文档身份及文件哈希，再打开副本建模，
保留每次保存的开始、返回和错误记录。旋转支架的配合支持aligned、anti_aligned和closest，
默认closest保留声明姿态，仍需以实际组件变换和约束状态验收。

`examples/bracket_shaft_plate.json` 是7组件、5种零件、15配合的静态测试件，包含孔板底座、
两只旋转L支架、竖轴、上部孔板和两个导向块。它用于API验收，不代表制造或承载设计。
`release_tools/configure_local_dumps.ps1` 可在管理员确认后仅对SLDWORKS.exe启用本地小转储，
保存旧设置并支持恢复。启用记录不等于已取得崩溃转储，不能凭一次通过宣称宿主内部故障根因已证实。

已有零件通过本机文件选择器上传并固定哈希。`inspect.py` 只读打开任务副本，读取
GetExtremePoint精确边界、实体体积和圆柱面，随后恢复原活动文档。生成装配前另存
独立输出零件，保留原始文件。只支持SLDPRT输入；已有SLDASM必须带完整依赖，当前
界面尚未接入该格式。

对自己的已完成任务进行自然语言修改时，模型保留未改变的参数，输出完整新方案，
在新目录重新构建。当前不宣称能通用修改任意导入模型的历史特征树。

交付包含SLDASM/SLDPRT、STEP、BOM、四视图预览、设计方案及依赖ZIP。ZIP逐项核对
SHA256；包内含geometry-verification.json和SHA256SUMS.txt，最终ZIP哈希另存于完整验收回执，
避免循环哈希。修订前后读取前版原生文件及规格文件哈希，确认前版保留。BOM按实际实例统计数量，列出原生材料、密度、单件及合计质量。标准材料必须来自本机实际材料库；自定义密度须明确给出名称和kg/m³数值。
材料、实际质量和体积在保存重开后复核，所有材料已知时再与原生装配总质量核对。存在未知材料时，总质量及相应BOM质量单元格保留未知；原生默认读数单独记录。
自定义密度修改目前只验收单配置零件，STEP只核验几何，不宣称保留材料或配合。STEP用于几何交换，原生配合保留在SLDASM中。
装配STEP使用独立几何导入核对实例实体数量、精确边界及体积。检查期间临时使用
经典导入器及多实体几何映射，关闭交互式诊断，所有选项和原工作目录在结束后回读恢复。
仅关闭本任务拥有的文档以避免STEP内嵌产品名与原生文档冲突，其他文档保留。

API依据包括SolidWorks的[配合实体引用类型](https://help.solidworks.com/2022/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IMateEntity2~ReferenceType2.html)、
[导入选项](https://help.solidworks.com/2019/English/api/swconst/FileOpenOptionsGeneral.htm)及
[多实体结构映射](https://help.solidworks.com/2024/english/api/swconst/SolidWorks.Interop.swconst~SolidWorks.Interop.swconst.swImportNeutralAssemblyStructureMapping_e.html?id=2.10.1.428)。
常量从安装的2024类型库解析，并以实际读回值确认，不能把返回false的新布尔值误作设置失败。

已安装技能的知识只作为路线目录，不能把技能名称当作已验证能力。真螺纹、齿轮、
任意圆角、复杂运动和制造工程图需要各自的2024原生验收。本地复用现有MIT原生帮助
函数，vendor及上游SolidworksMCP源码保持原样。
